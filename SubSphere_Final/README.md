# SubSphere 3.1

## Run locally (Windows / VS Code)

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m streamlit run subscription_manager.py
```

Open http://localhost:8501

## Features
- Add, edit, search, filter, pause, cancel and delete subscriptions
- Weekly, monthly, quarterly and yearly billing
- Monthly-equivalent and annual projections
- Renewal reminders and upcoming payments
- Category analytics and charts
- Manual payment history
- CSV export/import and JSON backup
- Monthly budget indicator
- Dark glass-style dashboard

## Local database
The app creates `subsphere.db` automatically in the current working directory.

## Cloud database (recommended before public launch)
The app can use Supabase when secrets are configured. Create two tables in Supabase SQL Editor:

```sql
create table public.subscriptions (
  id bigint generated by default as identity primary key,
  name text not null,
  price numeric not null,
  currency text not null default 'INR',
  category text not null,
  billing text not null,
  next_payment date not null,
  status text not null default 'Active',
  website text default '',
  notes text default '',
  created_at timestamptz not null default now()
);

create table public.payments (
  id bigint generated by default as identity primary key,
  subscription_id bigint references public.subscriptions(id) on delete cascade,
  name text not null,
  amount numeric not null,
  currency text not null,
  paid_on date not null,
  note text default ''
);
```

Then add Streamlit secrets in the app's cloud settings:

```toml
[supabase]
url = "https://YOUR_PROJECT.supabase.co"
key = "YOUR_SUPABASE_SECRET_KEY"
```

Use a server-side secret only. Never commit `.streamlit/secrets.toml` or secret keys to GitHub.
For a real multi-user app, add Supabase Auth and Row Level Security policies before allowing users to store their own records. This starter version does not include login and should not be treated as a secure multi-user product.

## Deploy on Streamlit Community Cloud
1. Create a GitHub repository.
2. Upload `subscription_manager.py` and `requirements.txt`.
3. Open https://share.streamlit.io/ and sign in with GitHub.
4. Create an app, select your repository and branch.
5. Set the main file path to `subscription_manager.py`.
6. Deploy.
7. Configure Supabase secrets in the app settings if using cloud storage.

Do not rely on local SQLite files for durable cloud storage. Configure Supabase before using the hosted app for important data.


## SubSphere 3.1 Payment Centre (sandbox only)

The Payment Centre adds safe demo records for token references, a simulated recurring-mandate lifecycle, an HMAC-SHA256 webhook verification lab with duplicate-event protection, and an India/global provider capability comparison. It does **not** connect to a live gateway, collect real payment details, or debit money.

### Run

```powershell
python -m pip install -r requirements.txt
python -m streamlit run subscription_manager.py
```

Open **Payment Centre (Sandbox)** in the sidebar. Use fake values only. The helper module `payment_security.py` creates local demo tables in the same SQLite database.

### Security boundary

Never enter or store real card numbers, CVV, UPI PIN, OTP, bank passwords, or bank account credentials. Production card/UPI linking must use the provider-hosted checkout/SDK and provider-issued token references. Keep API secrets server-side, verify webhook signatures against the exact raw request bytes, use unique event IDs for idempotency, and fetch final payment status server-to-server.

This version deliberately has no live payment adapter or production API-key settings. Real merchant onboarding, KYC, gateway activation, customer mandates and any live payment processing must be handled by an eligible adult/business and comply with current provider, RBI and NPCI requirements.
